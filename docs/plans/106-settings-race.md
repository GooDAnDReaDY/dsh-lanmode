# План реализации: Устранение гонки запасного пути конфигурации со службой настроек (#106)

## Проблема и контекст
На production после обновления ядра DSH до `0.1.5-alpha.1` плагин перестал открывать сетевые слушатели. Причина:
1. В `lib/index.js` `inject` был объявлен только как `['webServer']` без `settings`.
2. В `apply()` запускался таймер `setTimeout(() => once(ctx, config), 2000)`.
3. На `0.1.5-alpha.1` сборка дерева плагинов занимает более 10 секунд. Таймер срабатывал первым с пустой конфигурацией ряда (`config: {}`), применял умолчания схемы (`mode: 'proxy'`), и выставлял `started = true`.
4. Когда `ctx.inject(['settings'])` наконец срабатывал с реальными настройками из `settings.yaml`, выполнение прерывалось по `if (started) return`.
5. Ошибки регистрации настроек перехватывались блоком `catch (alreadyRegistered)` и тихо глушились.

## Что сделано
1. **Декларация зависимостей**: `export const inject = ['webServer', 'settings']`. Cordis гарантированно ждет инициализации обеих служб перед вызовом `apply()`.
2. **Устранение таймера-гонки**: Удален 2-секундный таймер в `apply()`. Настройки считываются синхронно из `ctx.settings`.
3. **Обработка ошибок регистрации**: Блок `catch (err)` логирует ошибку через `say()`, фиксирует `configWarning` и переводит плагин в режим работы на умолчаниях с явной фиксацией статуса.
4. **Реактивная реконфигурация**: Подписка на `scope.subscribe()` обновляет активную конфигурацию и динамически перезапускает слушателей прямого моста (`syncListener`).
5. **Диагностика и прозрачность**: Поля `configSource` ('settings' | 'row' | 'defaults') и `configWarning` выводятся в `/dsh-lanmode/health` и `hostReport`.
6. **Безопасное значение по умолчанию**: В схеме `Config` значение `mode` по умолчанию изменено с `'proxy'` на `'auto'`, предотвращая непреднамеренное отключение сетевых слушателей.

## Проверки
- Модульные тесты `test/settings-race.test.mjs` проверяют `inject`, `Config.mode`, `apply()`, ошибки регистрации и `health.js`.
- Все 155 тестов набора проходят успешно (`npm test`).
