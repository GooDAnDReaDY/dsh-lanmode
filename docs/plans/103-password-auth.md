# План реализации: Аутентификация по логину и паролю для защиты любого входа в DSH (#103)

## Контекст и цели
Пользователь поставил задачу:
- Защитить **любой вход** в DeepSeek Harness (как по сети LAN/WAN, так и локально) по имени пользователя и паролю.
- Разработать **красивую страницу логина** в фирменной эстетике DSH (Catppuccin Mocha / Dark).
- Предоставить возможность включения, настройки логина/пароля и учетных данных в панели настроек плагина.

## Архитектура решения

### 1. Схема конфигурации (`lib/index.js`)
- `passwordAuth`: `z.boolean().default(false)` — флаг активации аутентификации.
- `authUser`: `z.string().default('admin')` — имя пользователя.
- `authPassword`: `z.string().default('')` — прямой пароль (для быстрой настройки).
- `authPasswordRef`: `z.string().default('')` — ссылка на секрет в сервисе credentials.
- `authSessionDays`: `z.number().default(30)` — время жизни сессии в днях.

### 2. Модуль аутентификации и сессий (`lib/auth.js`)
- Управление сессиями:
  - Выпуск защищенных токенов через `crypto.randomBytes(32).toString('hex')`.
  - Хранение активных сессий с привязкой к User-Agent, IP и времени истечения.
  - Персистентность сессий через файл или в `DeviceRegistry`.
- Валидация пароля:
  - Поддержка прямого пароля или хеша.
  - Безопасное по времени сравнение строк через `crypto.timingSafeEqual`.
- Защита от перебора (Brute-force protection / Rate limit):
  - Ограничение до 5 неверных попыток с одного IP в течение 5 минут.
  - Блокировка на 30–60 секунд с возвратом `Retry-After`.

### 3. Фирменная страница логина (`lib/login-page.js`)
- HTML/CSS страница без внешних CDN (полностью автономная, zero-dependency).
- Цветовая палитра DSH Catppuccin Mocha (`#11111b`, `#181825`, `#313244`, `#cdd6f4`, акценты `#6366f1` / `#89b4fa`).
- Карточка по центру экрана:
  - Иконка замка/логотипа DeepSeek Harness.
  - Заголовок «DeepSeek Harness», подзаголовок «Вход в систему управления агентами».
  - Поле ввода «Имя пользователя» (с автозаполнением `username`).
  - Поле ввода «Пароль» (с переключателем показать/скрыть пароль).
  - Чекбокс «Запомнить меня на 30 дней».
  - Кнопка «Войти» с анимацией отправки.
  - Блок отображения ошибок валидации и предупреждений о блокировке.
  - Внизу: статус сети (HTTPS/LAN) и кнопка быстрого QR-кода.
- Адаптивность: Safe area insets, 16px font-size на iOS (anti-zoom), 44px touch targets.

### 4. Сетевой шлюз и эндпоинты (`lib/bridge.js` и `lib/index.js`)
- В `lib/bridge.js`:
  - Если `passwordAuth` включен:
    - Проверять наличие валидной cookie `dsh_auth_session`.
    - Исключать служебные эндпоинты: `/dsh-lanmode/auth/*`, `/favicon.ico`, `/dsh-lanmode/ca.crt`.
    - Если сессии нет:
      - Для браузерных запросов (`Accept: text/html` или навигация): отдавать страницу логина.
      - Для фоновых API-запросов и WebSocket: возвращать `401 Unauthorized` (`x-dsh-auth-required: 1`).
- В `lib/index.js`:
  - Эндпоинты:
    - `POST /dsh-lanmode/auth/login`: проверка логина/пароля, выдача `Set-Cookie: dsh_auth_session=...; Path=/; HttpOnly; SameSite=Lax`.
    - `POST /dsh-lanmode/auth/logout`: аннулирование сессии, очистка cookie.
    - `GET /dsh-lanmode/auth/session`: проверка статуса текущей сессии.
- Клиентский гейт в `lib/shim.js`:
  - Если страница открыта напрямую через петлю без `bridge.js`, `shim.js` проверяет статус авторизации и при отсутствии сессии монтирует модальное окно/экран логина, не давая инициализировать интерфейс DSH до ввода учетных данных.

### 5. Панель настроек плагина (`lib/client.js`)
- В `LanModeCard` добавить блок «Аутентификация по логину и паролю»:
  - Чекбокс `passwordAuth` («Вход по логину и паролю»).
  - Текстовое поле `authUser` («Логин»).
  - Поле `authPassword` с возможностью скрыть/показать значение.
  - Поле `authPasswordRef` («Ссылка на секрет в credentials»).
  - Кнопка «Сохранить».
- Кнопка «Выйти из аккаунта (Logout)» в интерфейсе.

### 6. Модульные тесты (`test/password-auth.test.mjs`)
- Проверка валидации учетных данных и защиты от перебора.
- Проверка генерации сессионных токенов и cookies.
- Проверка перехвата запросов в `bridge.js` при включенной аутентификации.
- Проверка рендеринга страницы логина.
- Проверка эндпоинтов `/auth/login` и `/auth/logout`.
