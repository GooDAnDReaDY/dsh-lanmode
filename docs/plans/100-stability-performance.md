# План реализации: Оптимизация стабильности, производительности стриминга и устранение оверинжиниринга (#100)

## Контекст и цели
В ходе архитектурного аудита dsh-lanmode выявлены узкие места производительности, риски повреждения сетевых протоколов и избыточные вмешательства в пользовательский интерфейс (оверинжиниринг):
1. **Блокировка Event Loop в DeviceRegistry**: `lib/devices.js` при каждом HTTP/WS запросе вызывал синхронный `fs.writeFileSync`, замораживая процесс Node.js при параллельном трафике.
2. **Задержка стриминга токенов LLM (SSE)**: `lib/bridge.js` сжимал через Brotli/Gzip ответы с типом `text/event-stream`, что приводило к буферизации токенов и задержкам вывода ответов модели в веб-интерфейсе.
3. **Риск падения WebSocket (Error 1002 Protocol Error)**: `lib/bridge.js` внедрял сырые байты пинга `[0x89, 0x00]` напрямую в дуплексный поток сокета во время активной передачи фреймов.
4. **Паразитный оверинжиниринг в мобильном слое**:
   - `lib/mobile-nav.js` перехватывал нажатие клавиши `Enter` на всех textarea через `e.stopPropagation()`.
   - `lib/shim.js` глобально подменял `HTMLElement.prototype.focus` и блокировал фокус на 2.5 секунды.
   - `lib/mobile-styles.js` принудительно скрывал соседние плагины (`terminal`, `git-graph`, `perf`) через `display: none !important`.
   - `lib/client.js` бесконечно опрашивал `/dsh-lanmode/devices` и `/dsh-lanmode/tunnel`, даже когда карточка настроек была свёрнута.
5. **Шумные сбои брандмауэра**: `lib/firewall.js` выполнял команды с повышенными привилегиями из непривилегированного процесса, выдавая ошибки в лог.

## Архитектура решения

### Блок 1. Асинхронная отложенная запись DeviceRegistry (`lib/devices.js`)
- Сохранение состояния в памяти (`Map`) происходит мгновенно при каждом `touch()`.
- Запись на диск откладывается (`scheduleSave`) с дебаунсом (5 секунд) и таймером с `unref()`, предотвращая блокировку Event Loop.
- Критические действия (`revoke`, `revokeAll`) инициируют немедленный форсированный сброс (`flush()`).
- Добавлен метод `flush()` для гарантированного сохранения при завершении работы плагина.

### Блок 2. Исключение SSE из потокового сжатия (`lib/bridge.js`)
- Проверять заголовок `content-type`: если ответ содержит `text/event-stream` или выставлен `x-accel-buffering === 'no'`, сжатие отключается.
- Чанки стриминга LLM транслируются напрямую в `res` без буферизации компрессора.

### Блок 3. Безопасный Keep-Alive для WebSocket (`lib/bridge.js`)
- Удалить инъекцию сырых байтов `[0x89, 0x00]` в поток сокета.
- Включить стандартный TCP Keep-Alive на сокетах клиента и апстрима:
  `socket.setKeepAlive(true, 25000)`
  `upstreamSocket.setKeepAlive(true, 25000)`.

### Блок 4. Очистка оверинжиниринга мобильного слоя и клиента
- `lib/mobile-nav.js`: убрать глобальный `stopPropagation` на клавишу `Enter`.
- `lib/shim.js`: удалить подавление `HTMLElement.prototype.focus`.
- `lib/mobile-styles.js`: удалить правило с `display: none !important` для чужих плагинов (`[data-dsh-plugin*="terminal"]`).
- `lib/client.js`: запускать таймеры опроса `/dsh-lanmode/devices` (20с) и `/dsh-lanmode/tunnel` (10с) только при открытой карточке (`open === true`).

### Блок 5. Безопасное выполнение проверок брандмауэра (`lib/firewall.js`)
- Корректная обработка отсутствия прав администратора без генерации исключений.

### Блок 6. Модульные тесты и верификация
- Тесты в `test/stability-performance.test.mjs`:
  - Проверка отсутствия блокирующего `writeFileSync` при частых `touch()`.
  - Проверка пропуска компрессии для `text/event-stream`.
  - Проверка корректной работы `DeviceRegistry.flush()`.
  - Проверка очистки стилей и невмешательства в `Enter`/`focus`.
- Прогон всего тестового набора (`npm test`).
