## Что добавлено и изменено

### 1. Блокировка административных действий для роли `guest` (#141)
* **Централизованный реестр `isAdministrativeRoute` (`lib/access.js`)**: Устранен разрозненный список путей. Опечатка `/dsh-lanmode/api/devices/revoke` исправлена на канонический путь `/dsh-lanmode/devices/revoke`.
* **Полное покрытие административного периметра**: В список запрещенных для гостевой роли маршрутов включены:
  - `/dsh-lanmode/devices/revoke` (отзыв конкретной сессии);
  - `/dsh-lanmode/devices/kill-all` (сброс всех сессий);
  - `/dsh-lanmode/api/devices/revoke-others` (отзыв чужих сессий);
  - `/dsh-lanmode/tunnel/toggle` (включение/выключение WAN Cloudflare-туннеля);
  - `/dsh-lanmode/devices` (список подключенных устройств с IP и User-Agent);
  - `/api/settings` и `/api/plugins` (системные настройки ядра DSH).
* При попытке вызова любого из этих маршрутов гостем возвращается строго `403 Forbidden` с телом `{ error: "Forbidden: Guest access does not permit administrative actions" }`.

### 2. Встроенная защита эндпоинтов (Defense-in-Depth, #142 & #132)
* **Шлюз `verifyAdminAccess` (`lib/access.js`, `lib/index.js`)**:
  - Обработчики маршрутов плагина больше не рассчитывают исключительно на фильтрацию внешнего моста `bridge.js`. При прямом обращении к сетевому порту DSH запросы проверяются по принципу Fail-Closed.
  - Если включена аутентификация по паролю (`passwordAuth: true`), доступ к `/devices`, `/devices/revoke`, `/devices/kill-all`, `/tunnel/toggle` требует валидной сессии `dsh_auth_session` (иначе `401 Unauthorized`).
  - При выключенной парольной защите прямой доступ разрешен только с доверенного петлевого интерфейса (loopback `127.0.0.1` / `::1`) либо с IP-адресов, наделенных ролью `admin` по CIDR-правилам. Гостевые и заблокированные адреса получают `403 Forbidden`.
* **Защита от CSRF**:
  - Все модифицирующие запросы методом POST проверяются функцией `isTrustedSameOrigin`.
  - Запросы с заголовком `Sec-Fetch-Site: cross-site` безусловно отклоняются с кодом `403 Forbidden`.
  - Проверяется соответствие заголовков `Origin` и `Host`.

### 3. Безопасность конфигурации по умолчанию и предупреждения о WAN (#132)
* В `raiseListener` добавлена проверка периметра: если шлюз запускается на внешних интерфейсах с пустым списком `allow` и при этом отключена аутентификация по паролю (`passwordAuth: false`), в лог выводится явное предупреждение `SECURITY WARNING` о рисках неавторизованного доступа.

### 4. Санитайзинг Git-репозитория (#135)
* Служебные файлы внутренней разработки (`AGENTS.md`, `index.md`, `docs/plans/`, `docs/testing/`) сняты с отслеживания в Git (`git rm --cached -r`).
* Файлы физически сохранены на рабочей машине разработчика, но больше не попадают в публичный Git-индекс и GitHub.
* Файлы внесены в `.gitignore`.
* Из корня репозитория удалены остаточные архивы прошлых релизов (`.tgz`).
